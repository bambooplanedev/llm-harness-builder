# Власні діалекти й підключення для `proxy`

Проксі-запис читає запити агента в одному з кількох форматів API (його *діалектів*) і відрізняє агентів за кількома
заголовками (його *підключеннями*). І те, і те можна замінити чи доповнити власними файлами.

**Власний діалект — це код, і він працює з повною довірою.** Файл `.mjs`, який ви передаєте через `--dialect`,
імпортується в процес проксі: він бачить `process.env`, мережу й ваші файли, як і будь-яка програма, яку ви
запускаєте. Перевірки тут ловлять помилки, а не зловмисного автора. Завантажуйте лише файли, які написали або
прочитали самі, і тримайте їх поза будь-яким репозиторієм, який може редагувати агент, що його ви записуєте: агент,
який перепише файл, отримає запуск свого коду при наступному старті. Підключення — звичайний JSON, він нічого не
виконує.

## Як передати файли

    llm-harness-builder proxy --upstream=http://127.0.0.1:11434 --port=8090 --name=ollama \
      --dialect=/abs/path/ollama-chat.mjs --connection=/abs/path/my-harness.json

Обидва прапорці можна повторювати. Шляхи мають бути абсолютними; відносний шлях, неіснуючий файл, тека чи файл без
розширення `.mjs` (діалект) або `.json` (підключення) — відмова на старті з назвою файлу. Розширення перевіряється
на справжньому файлі, після символьних посилань. Після звичайних стартових рядків проксі друкує по одному рядку на
кожен власний файл, у порядку прапорців:

    dialect ollama-chat from /abs/path/ollama-chat.mjs
    connection my-harness from /abs/path/my-harness.json (replaces built-in)

Суфікс з'являється, коли файл замінив вбудований з тим самим id чи назвою. Шлях ніколи не пишеться в `runs/`.

Пакет постачає робочу пару в `examples-dialects/` (`ollama-chat.mjs` — для рідного `/api/chat` в Ollama — і
`my-harness.json`). Скопіюйте їх із теки пакета й редагуйте копії.

## Файл діалекту

Файл `.mjs`, чий `export default` — об'єкт:

```js
export default {
  id: 'my-format',                 // /^[a-z0-9][a-z0-9-]{0,63}$/; id вбудованого його замінює
  label: 'POST /my/route',         // як помилки називають маршрут
  matches(method, pathname) {},    // boolean, синхронно
  keyOf(payload) {},               // { key, taskText, len, model }, синхронно
  toolResults(payload, calls) {},  // масив, синхронно
  async readReply(chunks, contentType) {},  // NormalizedResponse
  async partial(chunks, contentType) {},    // рядок або undefined
}
```

- `id`: також назва діалекту в рядках логу. Два власні файли з одним id — відмова. Вбудовані id: `openai-chat` і
  `anthropic`.
- `matches(method, pathname)`: чи записується запит як цей формат. `method` може бути `undefined`; `pathname` без
  query. Запити, яких не впізнав жоден діалект, проходять без запису. Спершу питають власні діалекти, у порядку
  прапорців, потім вбудовані.
- `keyOf(payload)`: `payload` — розібране тіло запиту з уже прибраними ключами. Поверніть:
  - `key`: рядок; запити з однаковим `key` належать одному прогону. Беріть те, що не змінюється протягом розмови,
    наприклад системний промпт і перше повідомлення користувача.
  - `taskText`: перший текст користувача, як його набрав агент.
  - `len`: ціле >= 0, яка довга розмова наразі (зазвичай кількість повідомлень). Запит з меншою кількістю
    повідомлень, ніж останній, який бачив прогін, починає новий прогін (підказка `session` підключення замінює це
    правило: прогін тоді — це підключення, сесія й агент).
  - `model`: назва моделі, `''`, коли в тілі її нема.
- `toolResults(payload, calls)`: результати, які цей запит несе для викликів попередньої відповіді. `calls` — це
  `ToolCall`, записані на тій відповіді. Поверніть `[]`, коли в запиті нема попереднього повідомлення асистента.
  Кожен елемент — `ToolResultSeen`.
- `readReply(chunks, contentType)`: `chunks` — байти тіла відповіді, `contentType` — заголовок відповіді (`''`, коли
  його нема). Розберіть тіло JSON або потік за ним і поверніть `NormalizedResponse`.
- `partial(chunks, contentType)`: викликається, коли відповідь обірвано. Поверніть текст, розкодований досі, ніколи
  не сирий синтаксис потоку, або `undefined`, коли нічого не читається.

Форми в TypeScript:

```ts
type ToolCall = { callId: string; name: string; args: Record<string, unknown>; backendId?: string }
type ToolResultSeen = { call: ToolCall; output: string; error?: true }
type NormalizedResponse = {
  content: string                 // обов'язково; '' для відповіді лише з викликами
  toolCalls: { name: string; args: Record<string, unknown>; backendId?: string; argsError?: string }[]  // обов'язково
  reasoning?: string
  usage?: { promptTokens: number; completionTokens: number }
  truncated?: boolean             // сервер зупинився на ліміті токенів
  raw: unknown                    // відповідь як розібрана, лишається в записі
}
```

`callId` призначає проксі. `backendId` — id, який виклику дав сервер, якщо дав; формат без id (як в Ollama) його не
ставить, і `toolResults` зіставляє результати з `calls` за порядком.

Форма відповідей власного діалекту перевіряється на кожному виклику. Неправильна форма, як-от Promise із `keyOf`,
`len: NaN` чи `readReply` без `toolCalls`, рахується як виняток. Що б діалект не кинув, запит пересилається без змін,
і агент отримує відповідь upstream. Проксі пише в лог рядок з назвою діалекту й методу: виняток у `matches` означає
«не цей формат»; виняток у `keyOf` чи `toolResults` — нічого не записується, а сесії лишаються як були; виняток у
`readReply` лишає в ході подію `error`; виняток у `partial` рахується як `undefined`.

До 1.0 цей контракт може змінитись; зміну буде оголошено в README.

## Файл підключення

Об'єкт `.json`, що каже, як впізнати одного агента й очистити його текст завдання:

```json
{
  "name": "my-harness",
  "hints": { "session": "x-my-harness-session" },
  "taskStrip": [["<context>", "</context>"]],
  "hint": "for my harness: send x-my-harness-session with every request"
}
```

- `name` (обов'язково): за тим самим шаблоном, що й `id` діалекту.
- `hints` (обов'язково): який заголовок запиту несе який факт. Дозволені ключі: `session`, `agent`, `parent`,
  `agentType`, `requestClass`. Значення — назви заголовків малими літерами, що не несуть ключа: `authorization`,
  `proxy-authorization`, `x-api-key`, `api-key`, `x-goog-api-key` і `cookie` відхиляються. Значення заголовка
  зараховується, якщо це від 1 до 128 друкованих ASCII-символів. Запит без жодного заголовка підключення йде до
  наступного підключення.
- `taskStrip` (обов'язково, може бути `[]`): пари `[open, close]` непорожніх буквальних рядків. Кожен проміжок між
  ними, разом із тегами, вирізається з тексту завдання (незакритий іде до кінця).
- `auxiliary`, `compaction` (необов'язкові рядки): значення заголовка `requestClass`, що позначають допоміжний запит
  (заголовок, підсумок: примітка в головному прогоні сесії, без ходу) і стиснення контексту (хід, позначений
  приміткою). `auxiliary` потребує `hints.requestClass` і `hints.session`; `compaction` — лише `hints.requestClass`.
- `hint` (необов'язковий рядок): рядок для людей, що друкується на старті; `{port}` замінюється портом проксі.

Будь-який інший ключ відхиляється з його назвою.

## Заміна й порядок

- Власний файл з id чи назвою вбудованого замінює його; стартовий рядок це каже. Два власні файли з одним id чи
  назвою — відмова.
- Діалекти пробуються так: власні, у порядку прапорців; потім вбудовані, яких не замінено.
- Підключення пробуються спершу з підказками: власні з підказками (порядок прапорців), потім вбудовані з
  підказками, потім рівно одне підключення з порожніми `hints` — запасне. Вбудоване запасне — `generic`. Власне
  підключення з порожніми `hints` відхиляється, якщо воно не називається `generic` і тим не замінює його; після
  злиття запасне має бути рівно одне.

## Як перевірити свій файл

1. Запустіть проксі з файлом і `--upstream`, до якого можна дістатись. Відхилений файл зупиняє старт однорядковою
   причиною й ненульовим кодом виходу. Перевірте, що з'явився рядок `dialect ... from ...`.
2. Надішліть один запит вручну (`curl`) або від агента, з колом інструмента, якщо формат його має.
3. Прочитайте `runs/<id>.jsonl`: `task` першого рядка, події `tool_call` і `tool_result` та кількість ходів мають
   збігатися з тим, що зробив агент. Рядок у логу проксі, що починається з `not recorded:`, називає діалект, метод і
   причину, чому запит пропущено без запису.

`tests/own-files.test.ts` у репозиторії робить це для прикладу Ollama проти фейкового upstream; його схема — добрий
шаблон для тесту вашого файлу.
